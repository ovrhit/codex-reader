# CODEX — 학술 문헌 읽기 아카이브

읽고 있는 **논문**과 **책**을 등록하고, 어디까지 읽었는지 기록하는 Windows 데스크톱 앱입니다.
Electron으로 만든 **완전 로컬 앱**이며, 웹 서비스가 아닙니다. 모든 기록은 이 PC 안에만 저장됩니다.

## 실행

```bash
npm install
npm start
```

## 기능

### 논문
- **읽음 / 읽는 중 / 안 읽음** 상태 구분
- **태그**를 자유롭게 붙여 나중에 다시 찾기 (읽은 논문도 계속 기록 가능)
- DOI · 학술지 · 연도 · 원문 링크 · 메모 · 별점

### 책
- **목차 등록** → 장별로 읽음 체크, 전체 진척도 자동 계산
- 쪽 범위(`12-40`)를 넣으면 진척도를 **쪽 수로 가중** 계산, 없으면 장 개수 기준
- **발췌독 모드** — 읽을 장만 범위로 지정하면 그 범위만 진척도에 반영 (예: 3~5장만 읽는 경우)
- 범위 메모, 목차 없는 책을 위한 수동 진행률 슬라이더

### 공통
- 문헌마다 **표지(프로필) 이미지** — 온라인 검색 결과에서 자동, 또는 내 PC 파일 / 이미지 주소로 직접 지정
- **종합 스탯** — 총 문헌 수, 완독 수, 전체 진척도, 읽은 장/쪽 수, 연속 기록(streak), 평균 완독 소요일, 평균 별점, 최근 12개월 활동, 상태·태그 분포

## 온라인 검색 (선택 사항)

등록 창의 검색은 **거들 뿐**입니다. 인터넷이 없어도 모든 항목을 직접 입력해 등록·관리할 수 있습니다.

| 종류 | 출처 | 가져오는 것 |
|---|---|---|
| 논문 | **Crossref** (DOI 등록기관) | 제목·저자·연도·학술지·DOI·분야 태그 |
| 책 | **Open Library** | 제목·저자·출판사·ISBN·표지·**판본 목차** |
| 책 | **Google Books** | 제목·저자·출판사·쪽수·표지 |

API 키가 필요 없고, 검색어와 표지 이미지 요청 외에는 아무것도 외부로 보내지 않습니다.

## 목차 이미지 OCR

목차 편집기의 **IMAGE OCR** 패널에서 책의 목차 페이지를 찍은 사진·스캔본을 넣으면 목차 초안을 만들어 줍니다.
여러 장을 한 번에 고를 수 있고 고른 순서대로 이어 붙입니다. (PNG · JPG · BMP · WEBP · GIF, HEIC 는 미지원)

Windows 10/11 에 내장된 OCR 엔진(`Windows.Media.Ocr`)을 쓰므로 **설치할 것도, API 키도, 인터넷도 필요 없습니다.**
이 PC 에서 쓸 수 있는 언어는 앱이 자동으로 찾아 목록에 띄웁니다(한국어·영어·일본어 등).
OCR 언어 팩이 하나도 없으면 패널 자체가 나타나지 않고, 목차는 지금처럼 직접 입력하면 됩니다.

### 동작 방식

OCR 은 목차 페이지의 왼쪽 '제목' 열과 오른쪽 '쪽번호' 열을 **서로 다른 줄로 끊어서** 돌려줍니다(가운데 점선 리더가 갈라 놓기 때문). 그래서 줄 단위 텍스트를 그대로 쓰면 제목과 쪽번호가 따로 놉니다.
`src/js/toc-ocr.js` 는 대신 단어 바운딩 박스를 받아

1. **y 좌표**로 흩어진 조각을 한 행으로 다시 묶고
2. **왼쪽 x 좌표**를 군집화해 章/節 들여쓰기 단계를 복원하고
3. **오른쪽 끝의 숫자**를 쪽번호로 떼어냅니다 (본문 중간 숫자를 오인하지 않도록 이미지 폭의 68% 바깥에 있을 때만)

머리글("차 례", "CONTENTS")은 항목이 아니므로 걸러냅니다. 로마숫자 쪽번호(서문 vii 등)는 앞붙이라 쪽 범위에서 제외합니다.

### 정확도와 한계

해상도가 인식률을 가장 크게 좌우해서, 가로 2600px 미만이면 앱이 자동으로 확대(최대 3배)한 뒤 인식합니다.
한글 목차 13항목으로 실측한 결과:

| 입력 | 제목 | 쪽번호 | 들여쓰기 |
|---|---|---|---|
| 1000px 원본 (확대 없이) | 10/13 | 9/13 | 13/13 |
| 1000px → 자동 확대 | 10/13 | 12–13/13 | 13/13 |
| 2000px 고해상도 | 12/13 | 12/13 | 13/13 |

**완벽하지 않습니다.** `크리올→크리을`, `결론:→결론.` 같은 오인식이 남고, 실제 촬영본은 기울기·그림자·책등 굴곡 때문에 더 나쁠 수 있습니다.
그래서 OCR 결과는 곧바로 저장되지 않고 **편집기의 텍스트 칸에 들어가며, 오른쪽 미리보기로 확인·수정한 뒤 저장**하는 흐름입니다.
가로 2000px 이상으로, 그림자 없이 반듯하게 찍을수록 좋습니다.

### 구현 메모

`ocr.js` 가 `powershell.exe` 로 WinRT OCR API 를 호출합니다. 스크립트는 파일로 두지 않고 `-EncodedCommand`(base64 UTF-16LE)로 넘기는데, 패키징하면 소스가 `app.asar` 안으로 들어가 외부 프로그램이 읽을 수 없기 때문입니다.
결과 JSON 은 stdout 이 아니라 UTF-8 파일로 받습니다 — stdout 은 콘솔 코드페이지를 타서 한글이 깨집니다.

## AI 목차 인식 (선택)

설정 → **AI TOC READER** 에 본인 API 키를 넣으면 목차 편집기에 `AI로 읽기` 버튼이 생깁니다.
Windows OCR 보다 훨씬 정확하지만, **목차 페이지 이미지가 해당 업체 서버로 전송됩니다.**
키를 넣지 않으면 기능은 꺼진 채로 있고 Windows OCR · 수동 입력은 그대로 동작합니다.

| Provider | 비용 | 비고 |
|---|---|---|
| **Google Gemini** (기본) | **무료 티어 있음** — 이미지 입력 포함 | 분당 10~15회 / 하루 1500회 |
| Anthropic Claude | 유료 (종량제) | |
| OpenAI 호환 | 유료 | Base URL 직접 입력 (xAI Grok · OpenAI · OpenRouter 등) |

키는 `safeStorage`(Windows DPAPI)로 암호화해 `ai-config.json` 에 저장합니다.
`library.json` 과 분리돼 있어 **백업 내보내기에 키가 딸려 나가지 않습니다.**
렌더러에는 키 존재 여부와 끝 4자리만 전달됩니다.

### 한도를 넘으면

무료 티어 한도를 넘으면 요청은 **큐에 쌓이지 않고 그 자리에서 거부됩니다** (HTTP 429).
앱은 응답에 담긴 대기 시간(`Retry-After` 헤더 또는 Google 의 `retryDelay`)을 읽어
**그만큼 기다렸다가 자동으로 최대 2회까지 다시 시도**합니다. 기다리는 동안에는
`요청 한도 초과 — N초 뒤 자동 재시도` 로 남은 시간을 세어 보여 줍니다.
그래도 안 되면 몇 초 뒤에 다시 하라는 안내로 끝나고, 이미 읽은 사진의 결과는 유지됩니다.

잘못된 키(401·403)는 재시도 없이 즉시 알려 주고, 일시적 서버 오류(5xx)는 간격을 늘려 가며 재시도합니다.

## 목차 입력 형식

한 줄에 한 장씩. 미리보기로 확인하면서 편집할 수 있습니다.

```
1장 서론 | 1-24
  1.1 문제 제기 | 1-10
  1.2 선행 연구 | 11-24
2장 이론적 배경 | 25-70
3장 방법 .......... 71
```

- 쪽 범위: `제목 | 12-40` 또는 `제목 ..... 12`
- 줄 앞 **공백 2칸** = 하위 절 (3단계까지)
- 시작 쪽만 있으면 다음 장 시작 쪽 −1 을 끝 쪽으로 자동 보완

## 데이터 저장 위치

`%APPDATA%\CODEX\codex-data\` (설정 화면의 **폴더 열기** 버튼으로 바로 이동)

- `library.json` — 모든 기록
- `covers/` — 표지 이미지
- `backups/` — 하루 1회 자동 백업, 최근 20개 보관

설정 화면에서 백업 **내보내기 / 가져오기** 도 가능합니다.

## 글꼴

| 역할 | CSS 변수 | 스택 |
|---|---|---|
| 본문 | `--sans` | Pretendard → **Freesentation** → Segoe UI → 맑은 고딕 |
| 페이지 제목·헤딩 | `--display` | **Paperlogy** → Pretendard → Freesentation → Segoe UI |
| 숫자·서브 라벨 | `--mono` | JetBrains Mono → Cascadia Mono → Consolas |

Freesentation 과 Paperlogy 는 웨이트마다 패밀리 이름이 따로 설치되는 글꼴이라
(`Freesentation 7 Bold`, `Paperlogy 8 ExtraBold` 등), 그대로 쓰면 `font-weight` 가 먹지 않습니다.
`styles.css` 상단의 `@font-face { src: local(...) }` 18개로 각각 하나의 패밀리에 묶어
100~900 웨이트가 정상 동작하도록 했습니다. 설치된 글꼴만 참조하므로 네트워크를 타지 않고,
글꼴이 없는 PC 에서는 자동으로 다음 후보로 넘어갑니다.

### 표기 규칙

- **`--mono` 서브 글꼴이 쓰이는 자리는 전부 영어**입니다 — `READING ARCHIVE`, `LIBRARY`,
  `TABLE OF CONTENTS`, 필드 라벨(`TITLE`, `AUTHORS`, `TOTAL PAGES`…), 상태 배지(`READ` / `READING` /
  `UNREAD` / `EXCERPT`), 단위(`CH`, `P`, `DAYS`). 한국어 설명이 필요하면 본문 글꼴의 `.hint` 로 내립니다.
- 본문 글꼴 영역(버튼, 안내문, 사이드바, 태그)은 한국어를 씁니다.
- 글자에는 그라데이션을 쓰지 않습니다. 강조는 단색(`--cy`)으로 처리합니다.

## 설치 파일(exe) 만들기

```bash
npm run dist
```

`dist/` 에 두 가지가 생성됩니다.

| 파일 | 설명 |
|---|---|
| `CODEX-Setup-1.0.0.exe` | 설치 관리자 (설치 경로 선택 · 바탕화면/시작 메뉴 바로가기 · 제거 지원, 관리자 권한 불필요) |
| `CODEX-Portable-1.0.0.exe` | 설치 없이 바로 실행하는 포터블 실행 파일 |

설치 관리자만 / 포터블만 만들려면 `npm run dist:installer` 또는 `npm run dist:portable` 을 씁니다.

> 코드 서명 인증서가 없어 실행 시 Windows SmartScreen 경고가 뜰 수 있습니다.
> **추가 정보 → 실행**을 누르면 됩니다. 서명하려면 인증서를 준비한 뒤
> `build.win.certificateFile` / `certificatePassword` 를 `package.json` 에 지정하세요.

데이터(`%APPDATA%\CODEX\codex-data\`)는 설치·제거와 무관하게 유지되므로,
개발 중 `npm start` 로 쌓은 기록을 설치본에서도 그대로 이어서 볼 수 있습니다.
